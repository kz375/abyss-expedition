# 1.2.6 护盾动画与代码检查

本次检查覆盖当前 src 游戏源码、web/java 服务端、web/public 前端，以及启动和构建脚本。检查方式为源码阅读、现有回归、针对性复现、真实 Chrome 浏览器测试和固定策略平衡模拟。源文件已经实际修改；还没有上传 GitHub 或部署到公网。

## 已修复

1. **满血时护盾不可见**：原先把护盾放在生命条剩余空间，满血剩余空间为零。现在灰色护盾在生命条上方的细轨道显示，和生命条统一使用最大生命作为比例基准。护盾超过最大生命时条形显示封顶，旁边仍显示真实数值。
2. **动画跳变**：保留同一战斗中的血条元素；生命与护盾从当前显示位置平滑过渡，连续点击不跳回上次起点；玩家黄色、敌人深黄色残影延迟消退。开启系统减少动画时立即更新。
3. **血条错色、召唤物血条丢失**：角色状态中的 Health/生命也使用绿色。编号召唤物不再误判为可选按钮，红色血条正常显示在首领下方。状态页面单独一行的护盾数值也参与绘制。
4. **选项漏识别与说明丢失**：兼容中文句号和冒号，包括“篝火：1.”；事件说明留在正文，选项成为按钮。已选择和已关闭的事件按钮都禁用。
5. **布局补丁互相覆盖**：清除了固定整页高度、760px 战斗窗及其多轮反向覆盖规则。页面自然滚动，桌面战斗日志最大 620px。补正手机和平板的单栏规则，血条保持较短并对齐。
6. **前两层精英比普通怪更脆**：精英同样使用开局生命基准，再应用精英倍率；普通怪仍保持高于最高开局生命、且最多高出 80 点的范围。最高初始生命从职业定义计算，不再硬编码 226。
7. **玩家被诅咒没有增伤**：受击结算现在执行 Curse 的增伤效果，和该状态描述一致。
8. **召唤当回合的首领保护空档**：生成召唤物后立即启用保护，防止当回合灼烧或反伤绕过保护。
9. **反伤虚增统计**：首领受保护时，反伤统计按实际掉血量记录为零。
10. **吸血敌人被反伤杀死后又复活**：已经死亡的攻击者不再从同次吸血技能恢复生命；未造成生命伤害时也不再凭空吸取 1 点。
11. **召唤物击败记录遗漏**：击败召唤物计入怪兽图鉴和普通/精英击杀数，一次只记一次，不额外发放金币或经验。
12. **Creator 斩杀边界**：保护中的首领不能被斩杀或虚增伤害统计；低于 10% 的召唤物可按被动规则斩杀，严格保留“小于 10%”条件。
13. **机关试炼入口失联**：之前改成具体事件卡后，没有再走旧的随机入口。现在第五层起完成事件卡、玩家仍存活时，保留 5% 的试炼遭遇机会，每局最多一次。
14. **中断事件会白白消耗次数**：取消“刚选路线就保存已消耗”的时机，事件完成后统一提交结果和路线状态。在选项处退出会恢复上一个完整检查点；结算成功后仍只能四选一。

## 平衡问题：尚不能认定完善

以下是测试脚本的诊断结果，不是玩家真实胜率。每个职业/难度使用种子 0–99，共 2400 次模拟；固定打法为低于 45% 血量优先用药，否则技能可用就施放；每层额外给予一次 35% 回血机会，金币够时补药，第二和第六层固定打精英，精英/首领奖励随机圣遗物。该脚本没有实际选择随机事件，因此只能比较同一策略下的趋势。

| 职业 | 探索者 | 冒险者 | 噩梦 | 超级噩梦 |
| --- | ---: | ---: | ---: | ---: |
| 战士 | 85/100 | 0/100 | 0/100 | 0/100 |
| 法师 | 83/100 | 7/100 | 1/100 | 0/100 |
| 游侠 | 81/100 | 8/100 | 0/100 | 0/100 |
| 造物主 | 97/100 | 35/100 | 4/100 | 0/100 |
| 圣骑士 | 100/100 | 42/100 | 5/100 | 0/100 |
| 死灵法师 | 81/100 | 2/100 | 0/100 | 0/100 |

- 圣骑士仍有明显续航优势，原因不只有冷却圣遗物：每回合护盾、治疗、眩晕共同降低了消耗。当前神圣审判冷却为 3，时光护符后为 2，已不能无限连续施放。
- 冒险者到噩梦的曲线比较陡。超级噩梦的后期精英与首领更需关注，不能因某一场战斗容易就整体加伤害。建议下一轮用真实四选一事件路线分别比较“只战斗”和“利用事件”的策略。
- 超级噩梦玩家基础属性是 3.7 倍，普通敌人生命 4 倍、攻击 2.4 倍。生命倍数和伤害倍数不同，不能只通过比较血量判断难度。
- 护甲是先减去防御再乘技能倍率；高防御和每回合护盾的组合很强。这是现有核心公式，本轮没有重写。
- 法师技能基础冷却已经为 1，而最低冷却限制为 1，所以时光护符对法师没有额外收益。需要在后续设计中说明这一点，或给出替代收益。
- 图鉴共 21 种，其中 2 种是首领；召唤池实际为 19 种普通怪，5% 概率精英化，并不召唤另一个首领。这是现有测试明确约束的行为。
- 机关失败在低血量时可能回血至开局生命下限，这是此前明确要求的规则，本次保留。

## 存档、部署与兼容性边界

- 保持存档格式 VERSION=2；新增检查覆盖旧档、种子随机状态、归档、损坏档保护及事件中断恢复。恢复的是检查点，不包含尚未结算的战斗逐回合状态。
- 试炼入场仍会保存一次，维持每局只进入一次的规则；中断试炼不会重新给一次试炼机会。
- 图鉴是独立的永久记录。它和远征存档不是一个原子事务，异常中断后重打一场战斗有可能再次增加击杀数；本次未把两套存储迁移成同一事务。
- 导出备份的文件数量/体积限制与导入校验没有完全统一，超大档案需要进一步处理；正常小档案的导出导入回归通过。
- 桌面 Swing 外壳及独立推箱子窗口仍有硬编码的双语/英文文案；本轮网页单语言检查通过，但不能据此声称桌面所有文字已完全本地化。
- tools/Package.java 的桌面安装包版本仍固定为 1.0.0，且会把 dist 整个目录作为打包输入。后续制作桌面发行版前应改为专用暂存目录，并同步版本。本次交付是网页更新包。
- 服务器为每位玩家启动一个 JVM，默认最多 8 个运行会话；并发能力和长时间运行仍需要实际部署环境测试。存档依赖服务器数据目录是否持久化，代码检查无法确认 Render 当前磁盘配置。
- 完成了本机 Chrome 的 320、390、768、851、1024、1280px 布局检查；没有在真实手机、Safari、Firefox、Windows 或 Linux 桌面逐台验证，也没有做公网负载测试。

- `java tools/Test.java`：兼容、机制、存档、语言与新增修复回归。

- `node web/tests/browser-test.mjs <Chrome可执行文件> http://127.0.0.1:8186`：隔离浏览器配置，实际检查菜单、语言、隐藏角色、战斗、刷新、事件选项、护盾动画、减少动画设置及响应式布局。运行前启动指向独立临时存档目录的本机服务器。
